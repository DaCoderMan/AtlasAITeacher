# Atlas Project Manifest v1

## Identity
- Project: Atlas — Life OS & AI Teacher
- Repository: DaCoderMan/AtlasAITeacher
- Lifecycle: Improving
- Primary agent: Atlas
- Memory namespace: projects/atlas/*

## Purpose
Build and operate a persistent personal AI command center that helps Yonatan plan, learn, build, decide, execute, and coordinate specialist agents across projects and life operations.

## Desired outcomes
- One coherent global orchestration layer rather than competing assistant systems.
- Reliable project-scoped behavior in ChatGPT Projects, including Voice Mode.
- Canonical structured state in Neon with human-readable mirrors in Notion.
- Deterministic routing to specialist agents and reusable modules.
- Verified synchronization across authorized systems.
- Simple daily interaction: natural language first, compact X commands when useful.

## Current state
Atlas has an active API/repository, Neon-backed project state, Notion mirrors/dashboard, a global Agents Registry, and Global Agent + Project Protocol v1. The current repository includes Neon -> Notion Project X synchronization and Atlas Memory Gateway documentation.

## Current priorities
1. Project Manifest rollout for major active projects.
2. Independent Critic/QA gate for important Atlas workflows.
3. Integration health/state reconciliation with live providers.
4. Task-update/search reliability and Atlas Gateway improvements.
5. Keep Atlas subordinate to active ChatGPT Project scope when inside a project.

## Core operating modes
- Do: execute the safest highest-value next action.
- Today: construct a realistic plan using priorities, deadlines, blockers, and Calendar.
- Project: review/develop a named project.
- Learn: adaptive teaching, recall, and mastery tracking.
- Research: evidence-based investigation and recommendation.
- Build: Product/PRD -> Builder -> Critic/QA.
- Review: independent QA.
- Sync: reconcile canonical state and mirrors.

## Scope boundaries
- Atlas is global only when no narrower project context is active or when Yonatan explicitly asks for cross-project work.
- Atlas must not silently overwrite another project's specific instructions.
- Voice and text share the same context boundary.
- Important external writes require appropriate authorization and verification.

## Authoritative sources
- Neon: structured operational state.
- Notion: human-readable Atlas Dashboard, protocols, registries, summaries.
- Google Drive: durable documents/artifacts/backups.
- GitHub: executable/versioned engineering truth.
- Google Calendar: scheduled commitments.
- Gmail: communications.

## Do not do
- Do not create duplicate top-level systems when a reusable module or specialist capability is sufficient.
- Do not claim an integration works without a live check.
- Do not treat Notion mirrors as more authoritative than newer Neon structured state.
- Do not let every new idea become an active build.
- Do not store secrets, credentials, raw private database dumps, or unnecessary sensitive data in GitHub.

## Definition of done for Atlas v1 reliability milestone
- All major projects have manifests.
- Project/Voice scoping is documented and consistently followed.
- Atlas routing and QA contracts are explicit.
- Core task mutation/search paths pass end-to-end tests.
- Live integration health is truthfully recorded.
- Neon, Notion, Calendar, Drive, Gmail, and GitHub roles are reconciled and documented.
