# Atlas Game Creation Pipeline 2.0

Reusable pipeline for educational Atlas games.

## Stages

1. Define learning outcome, player context, scope and real-world transfer target.
2. Build knowledge graph and mastery map before writing questions.
3. Run diagnostic or initialize a calibrated baseline.
4. Design the core gameplay loop around retrieval, decisions and consequences rather than passive exposition.
5. Create quests/levels, adaptive difficulty, rewards, boss battles and final real-world transfer quest.
6. Generate challenge pools with balanced/randomized answer positions and no systematic answer-length cues.
7. Attach confidence calibration, immediate explanatory feedback, Error Bank tags and Transfer Score.
8. Schedule spaced retrieval using shared Atlas learning primitives.
9. Persist the exact resume point after every round.
10. Instrument mastery, latency, attempts, recurrence of misconceptions, transfer and completion—not just XP.
11. QA for factual correctness, pedagogy, fairness, fun, difficulty curve and predictable-format leakage.
12. Version the game spec and content provenance; update certification tracks when official blueprints change.

## Certification mode

Certification games can be extensive. Readiness requires strong domain coverage, repeated realistic mock performance, low confident-error rate and demonstrated transfer to new scenarios. XP is motivational telemetry, not the pass criterion.

## Output contract

Each production game should define: slug, title, objective, domain/mastery map, challenge types, progression system, persistent state, boss criteria, final transfer quest, graphics slots, accessibility/localization needs, eval criteria and provenance.
